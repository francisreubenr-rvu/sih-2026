## Content rejection before visual adoption

The generator added unsupported claims despite explicit constraints: 42.4ms pipeline, 38–54ms across Chrome/Gecko,118MB memory,3.2MB model/runtime, Qwen2.5-VL and cryptographic DOM hashes. None may be published. Current server is Qwen2.5 text LLM reading approved geometric semantics; the actual detector/runtime sizes are in the model manifest; browser support claims require separate tests.

Generated team roles and target labels also differ from the source implementation and agreed proposed-role ledger. Preserve actual names and explicitly proposed roles. Any generated face/photo cannot be presented as a team portrait.

## Decision status

The generated screen was rendered in the browser and saved to Docs/stitch-landing-v01.png. At desktop width, its asymmetric hero and optical diagram explain the domain more directly, but its dense telemetry, multiple CTAs and raw icon-name text reduce clarity. This is a first visual review, not accessibility/performance certification. The final choice must assess hierarchy, domain clarity, real demo access, typography, mobile reflow, keyboard navigation, reduced motion and >90 Lighthouse budgets on the implemented result. Visual polish cannot authorize unsupported copy.

The local prototype remains functional while Website redesign proceeds separately. This is not the final comparison artifact.


## Selected direction

Retain the existing site's generous spacing, calm ivory/forest palette and restrained motion. Adopt the generated concept's asymmetric hierarchy and optical-aperture graphic, redrawn with accurate explanatory labels. Keep the real prototype's clean side-by-side privacy review as the product proof. Reject the raw generated HTML as a release candidate: it relies on runtime Tailwind CDN, external fonts/icons and contains fabricated implementation claims.

| Criterion | Existing preparation site | Stitch generated | Selection |
|---|---|---|---|
| First-screen clarity | Strong visual simplicity, obsolete project content | Domain-specific but overlong paragraph and technical jargon | New concise domain copy, current spacing |
| Hierarchy/personality | Centered oversized hero and race-line motif | More useful asymmetry/optical frame | Adapt asymmetry and aperture |
| Trust | Explicit uncertainty, now outdated | Unsupported numerical/capability assertions | Actual source/benchmark ledger only |
| Demo proof | Preparation-only | Decorative synthetic simulation | Real prototype screenshots and working access instructions |
| Implementation quality | Local assets and prior verified performance | CDN Tailwind, external icons rendered as text in observed screenshot | Local assets and measured final build |

This is a design judgment based on rendered artifacts, not a measured user preference score. The selected Website implementation now exists. Architecture and demo-dialog interactions were checked in the embedded browser; a 390px check found no horizontal overflow. Six fresh local Lighthouse runs scored 100 across all four categories; see Benchmarks/results/lighthouse-sightline-v01-summary.json. This does not establish WCAG conformance or human preference.
