Problem recap
The SIH problem asks for a privacy-preserving visual browser agent: local on-device vision model reads the screen, automatically detects and redacts sensitive/PII elements, and only then sends sanitized context to a server which produces UI actions or processed data.[onnxruntime]
Modern browser tooling makes this feasible: WebGPU and WebAssembly now allow running ML models client-side, and libraries like ONNX Runtime Web and Transformers.js expose simple JS APIs for computer vision tasks such as image classification and object detection directly in the browser.[huggingface][huggingface][huggingface][onnxruntime]
High-level architecture
Design the system as a browser extension + server with a well-defined contract for “sanitized context”:

Browser side (extension):
  * Content script + background/service worker.
  * Local vision pipeline using WebGPU/WebAssembly.
  * DOM + regex PII detection + CSS/canvas masking.
  * Sanitized context encoder (JSON / low-res image / feature map).
Server side:
  * LLM/VLM endpoint that consumes sanitized context.
  * Planner that outputs UI actions (click, type, scroll) or structured assistance.
Existing extensions such as ScreenMask and BlurIt already show that fully local PII detection and masking is viable and practical in real-time extensions, using DOM observers and pattern matching combined with on-page blurs or redaction before screenshots or sharing.[chromewebstore.google][microsoftedge.microsoft][chromewebstore.google]
Client-side vision stack
Use Transformers.js or ONNX Runtime Web to run a compact CV model with WebGPU acceleration, falling back to WASM if GPU is unavailable.[huggingface][huggingface][onnxruntime]
Transformers.js supports image classification, object detection, and segmentation tasks out-of-the-box, and can load ONNX models for browser inference.[huggingface][huggingface][techcommunity.microsoft]
ONNX Runtime Web provides onnxruntime-web with device options webgpu, webgl, wasm, and webnn, so you can target GPU or CPU depending on the user’s hardware, which is critical for the “client side resource utilization” evaluation metric.[onnxruntime]
For your use case:
Face & avatar detection: small face detection/segmentation model on ONNX, run via ONNX Runtime Web with deviceType: 'webgpu' when available.[linkedin][onnxruntime]
Screen region understanding: lightweight object detection (buttons, form fields, panels) or vision-language model (e.g., Florence-2 in ONNX) via Transformers.js v3 with WebGPU.[scrimba]
There are live demos of running image classification models like MobileNetV4 and Florence‑2 directly on WebGPU using Transformers.js pipelines, indicating that your architecture is realistic for current browsers.[huggingface][scrimba]
Privacy-preserving PII redaction
For PII detection and redaction, combine DOM-level semantics with vision-level bounding boxes:
Existing tools like ScreenMask and BlurIt detect emails, phone numbers, credit cards, IDs, and other PII using regex + DOM observers and then blur or replace them before screenshots or screen sharing.[microsoftedge.microsoft][chromewebstore.google][chromewebstore.google]
Extensions such as Cloak and Redact & Snap show auto-redaction workflows that blur or black out sensitive fields in screenshots and web pages entirely locally without sending data to servers, aligning perfectly with your privacy requirement.[chromewebstore.google][chromewebstore.google][chromewebstore.google]
Concretely on the client:
DOM-based filters:
  * Identify input[type=password], fields with autocomplete hints (email, name, phone), credit card patterns, and IDs using regex similar to ScreenMask’s pattern-matching approach.[chromewebstore.google][microsoftedge.microsoft]
  * Apply CSS masks (blur, pixelate, overlay rectangles), or replace text content with asterisks before rendering a screenshot or serializing context.
Vision-based filters:
  * Capture the viewport via tabs.captureVisibleTab or draw into an offscreen canvas.
  * Run vision model; get bounding boxes for faces, avatars, or sensitive widgets.
  * Paint over those regions (black boxes, heavy blur) in the canvas before encoding to PNG/WebP and sending to the server.
Your “sanitized context” payload can then be:
A redacted screenshot (faces and PII masked), plus metadata about element roles (button, input, etc.).
Or a structured JSON with layout (bounding boxes, element types, partial masked text), which minimises visual content while still giving the server enough state to reason and plan.
Server-side reasoning and actions
On the server, you can use any open-weights LLM/VLM running in the cloud during SIH, as long as it only sees anonymized data.[onnxruntime]
Design the server with:
Input schema:
  * Sanitized screenshot (optional).
  * Structured layout: list of elements with roles, positions, redaction flags, and masked text snippets.
Reasoning engine:
  * VLM (if using images) to interpret layout and visual cues.
  * LLM to read the structured layout and task description (“fill this form”, “navigate to X”, etc.), and produce a sequence of high-level UI actions.
The server returns actions like click(element_id), type(element_id, "value"), or scroll(direction="down"), which the extension executes using standard WebExtension APIs and DOM events.
